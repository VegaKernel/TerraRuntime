# Серверно-авторитетное движение игрока

TerraRuntime рассматривает пакет 13 как сообщение о вводе/состоянии клиента, а не как право клиента произвольно заменять серверную историю движения.

## Контракт границы

`RuntimePlayerMovementIngress` сначала применяет протокольно-независимый `VanillaPlayerMovementNormalizer`, а затем пропускает нормализованное сообщение через `RuntimePlayerMovementAuthority` до попадания команды в ограниченную authoritative-очередь.

Authority хранит историю по generation-safe `PlayerHandle`, а не только по переиспользуемому слоту игрока. При появлении более нового поколения история предыдущего владельца слота удаляется. Команда от старого поколения отбрасывается до очереди.

Текущие жёсткие правила намеренно консервативны:

- нечисловые/бесконечные поля по-прежнему отклоняет normalizer;
- скорость вне ограниченного серверного диапазона правдоподобия отклоняется до game-loop очереди;
- устаревшие поколения сессии отклоняются до game-loop очереди;
- отказ bounded queue не продвигает доверенную историю движения.

Production-граница также обнаруживает резкие скачки позиции относительно последней успешно поставленной в очередь позиции, монотонно измеренного времени и намеренно большого допуска на сетевой jitter/перемещение. Сейчас такие скачки наблюдаются и считаются, но **по умолчанию не отклоняются**. Это не позволяет незавершённой поддержке teleport/respawn превратиться в античит с ложными срабатываниями.

## Разрешения на исключительное движение

Строгая проверка позиции уже поддерживается authority для тестов и будущего включения в production. Серверная подсистема может выдать одно короткоживущее одноразовое разрешение, привязанное к точному поколению игрока, для:

- телепорта;
- respawn;
- смены mount-состояния;
- серверной коррекции позиции.

Разрешение может содержать ожидаемую целевую позицию и радиус. Устаревшая сессия не может воспользоваться разрешением, выданным новому владельцу того же wire-slot.

Production enforcement позиции следует включать только после того, как все легитимные источники резких перемещений начнут выдавать явные permits. До этого `PositionViolations` является телеметрией, а не основанием для kick/ban.

## Наблюдаемость

`RuntimePlayerMovementAuthoritySnapshot` публикует число принятых сообщений, отказов очереди, отклонений stale-generation и velocity, замеченных скачков позиции, строгих position-rejection, принятых exceptional moves, число отслеживаемых игроков и состояние строгого enforcement.

Эти счётчики описывают границу проверки. Сами по себе они не являются доказательством читерства без окружающего серверного состояния.

## Regression gate

Workflow `Player Movement Authority` собирает тестовый проект на .NET 11 и запускает существующие packet-13 ingress-тесты вместе с новым generation/history контрактом. Фокусный набор доказывает отклонение невозможной скорости, безопасность переиспользования поколения, одноразовые teleport permits, observe-only production режим позиции и транзакционность истории при отказе bounded queue.
