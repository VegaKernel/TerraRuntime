# Пиратский призрак AI122 и параметры пиратов (1.4.5.8)

Общий локальный checkpoint принят: Release, focused18618, один полный прогон1563155/1563157 с одним устаревшим roster-count failure и одним известным skip; исправленная группа roster/death/magic21 проходит с byte-identical production. Новая Windows NativeAOT/five smokes и Release/Native live82/49 с relay двух клиентов проходят. Typed Captain managed/Native проходят1778 проверок каждый; typed magic —24273 каждый. Native сохраняет public state/RNG и ограниченные компонентные проверки header/slot; managed State.Tick/private RNG/полные wire-проверки имеют отдельную область доказательства. Linux NativeAOT локально не проверен.

Captain `216` теперь использует связанного producer смерти, а Ghost `662` — ограниченный авторитетный путь внешнего update. Естественный выбор пиратов допускает капитана через существующего владельца изолированного рождения; корабль `491` и пушки `492` остаются ограждены. Production-интеграция и новая общая локальная acceptance checkpoint завершены.

Пиратский призрак662 использует собственный планировщик исходного AI122. Он преследует выбранного живого игрока с желаемой скоростью до4 и ускорением2/15, обновляет недопустимую цель и уменьшает alpha на5 при преследовании. Без подходящей цели скорость умножается на0.9, а alpha увеличивается на5. Переход без цели к alpha255 сохраняет запрос на существующую транзакцию исходного урона9999 и смерти; планировщик движения сам не публикует и не убивает NPC.

Разведение соседей обходит активных призраков по возрастанию физических слотов, при расстоянии строго меньше50. Нормализованное смещение даёт0.1 по каждой оси и ещё0.1 по X. Исходная нормализация нулевого расстояния даёт NaN. Runtime отклоняет весь выбранный план до применения, не подставляя нулевое смещение. Неизвестный владелец исходной цели, неизвестные размеры соседа и непредставленные мокрые/confused-контексты остаются явными границами допуска.

Параметры шести обычных пиратов сверены с источником: матрос212 life300/defense17, корсар213 life450/defense22, стрелок214 life225/defense14, арбалетчик215 life350/defense20, капитан216 life3000/defense30 и попугай252 life100/defense12. Призрак662 имеет размеры18×40, life500/damage75/defense22, без гравитации и столкновения с тайлами. Эффективная сложность1–4 покрывает Classic/Expert/Master с прибавкой GoodWorld. Произвольная дробная сложность этим блоком не допускается.

Независимые записи исполняют исходную сборку dedicated server:44 профиля призрака включают10 частных случаев AI,51 непрерывный шаг частного затухания и11 полных обновлений NPC. Тесты чистого планировщика сохраняют различие между частным запросом затухания и внешним CheckActive. Только что созданный NPC без живой цели отправляет обновление23, затем неактивный23, без28 и зачёта вторжения78; уже затухающий NPC с alpha250 проходит28→78→23. Связанный runtime теперь соединяет создание после капитана с внешними владельцами публикации и смерти, не выдавая частный запрос затухания за полный update.

Параметры сравниваются с42 записями Linux reference и42 настоящими вызовами Windows CLR4/x86 SetDefaults. Последние используют исходный Windows executable, а не Linux-сборку под CoreCLR. Некоторые округления knockback в Single различаются; проверка использует соответствующий платформенный fixture. Записи сохраняют хеши исходных сборок и фактические входные mode/GoodWorld.

Независимые связанные данные добавляют 16 настроенных случаев оригинала Linux и 16 настоящих Windows CLR4/x86, каждый повторён точно. Два durable Fact воспроизводят для платформы host 16 смертей капитана, 20 обновлений Ghost и 16 переходов lifecycle владельца вторжения. Managed-проверки сравнивают представленные поля тела, все 56 полей RNG, клонированный следующий результат, drops и буквальные кадры рождения/update/урона. Завершение проверяет существующий lifecycle и владельца вторжения с буквальным progression packet `98`; полная публикация `WorldRuntime` в порядке `98 → 82 → 7` этим не доказывается. Введённые projectile-offers отдельно подтверждают владение принятым курсором, а не совместимость исходного projectile→Captain.

Drops капитана, размещение Ghost, удаление родителя, зачёт вторжения и сохранённый baseline рождения принимаются до первого observer. Публикация сохраняет собственные принятые компоненты при вложенных смертях и исключениях. Точная occupation endpoint не позволяет отправить новичку повторное рождение после принятого baseline. Исходный первый свободный слот предпочтительнее replacement; насыщенное поколение выбранного слота вызывает отказ до HP, но более поздние защищённые или насыщенные слоты не блокируют ранний допустимый выбор. Исходное отсутствие доступного слота сохраняет GoodWorld-offer без выдуманного ребёнка.

Подготовка fade сначала читает providers игроков и контекста смерти, затем проверяет сохранённые raw target/status, таблицу NPC, RNG, вторжение, прогрессию, prelude, часы и daily-владельцев. Поздняя mutation отклоняется до HP и drops с сохранением нового состояния provider. Windows-путь движения явно сохраняет более широкие исходные промежуточные vector-значения; соответствующие платформе fixtures проверяют скорость третьего тика и GoodWorld knockback без tolerances. Все одиннадцать omission-контролей на копиях дают assertion failures без runner errors; восстановление проходит оба Fact. Проверенный Native subset использует typed state, публичные cloned-next/checkpoint проверки и ограниченные счётчики packet header/slot; private RNG/slot metadata и полные буквальные outbound-проверки остаются managed-only.

Контроли на копии production выявляют устаревшие параметры матроса, неверное ускорение, пропуск второго смещения X, нормализацию совпадающих центров и медленное затухание alpha; восстановленные копии проходят без ошибок runner. Доказательства не закрывают полный планировщик Main, произвольные импортированные статусы/цели, Летучего голландца491/пушки492 или FullVanillaAiParity. Выбор вторжения и владение смертью описаны в [частоте естественного спавна](natural-spawn-rate.md) и [правилах добычи NPC](npc-loot-rules.md).
