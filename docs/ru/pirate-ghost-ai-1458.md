# Пиратский призрак AI122 и параметры пиратов (1.4.5.8)

Ghost `662` остаётся `DefinitionOnly`: исходный планировщик и параметры проверены, но авторитетный владелец смерти и CheckActive за полный тик ещё не принят. Поэтому живой естественный выбор отклоняет капитана `216`, как и корабль `491`, сохраняя выбранный идентификатор без замены. Незавершённая интеграция капитана и Ghost сохранена отдельно от этого среза.

Пиратский призрак662 использует собственный планировщик исходного AI122. Он преследует выбранного живого игрока с желаемой скоростью до4 и ускорением2/15, обновляет недопустимую цель и уменьшает alpha на5 при преследовании. Без подходящей цели скорость умножается на0.9, а alpha увеличивается на5. Переход без цели к alpha255 сохраняет запрос на существующую транзакцию исходного урона9999 и смерти; планировщик движения сам не публикует и не убивает NPC.

Разведение соседей обходит активных призраков по возрастанию физических слотов, при расстоянии строго меньше50. Нормализованное смещение даёт0.1 по каждой оси и ещё0.1 по X. Исходная нормализация нулевого расстояния даёт NaN. Runtime отклоняет весь выбранный план до применения, не подставляя нулевое смещение. Неизвестный владелец исходной цели, неизвестные размеры соседа и непредставленные мокрые/confused-контексты остаются явными границами допуска.

Параметры шести обычных пиратов сверены с источником: матрос212 life300/defense17, корсар213 life450/defense22, стрелок214 life225/defense14, арбалетчик215 life350/defense20, капитан216 life3000/defense30 и попугай252 life100/defense12. Призрак662 имеет размеры18×40, life500/damage75/defense22, без гравитации и столкновения с тайлами. Эффективная сложность1–4 покрывает Classic/Expert/Master с прибавкой GoodWorld. Произвольная дробная сложность этим блоком не допускается.

Независимые записи исполняют исходную сборку dedicated server:44 профиля призрака включают10 частных случаев AI,51 непрерывный шаг частного затухания и11 полных обновлений NPC. Тесты чистого планировщика сохраняют различие между частным запросом затухания и внешним CheckActive. Только что созданный NPC без живой цели отправляет обновление23, затем неактивный23, без28 и зачёта вторжения78; уже затухающий NPC с alpha250 проходит28→78→23. Создание после капитана и внешняя публикация/смерть принадлежат отдельным владельцам интеграции.

Параметры сравниваются с42 записями Linux reference и42 настоящими вызовами Windows CLR4/x86 SetDefaults. Последние используют исходный Windows executable, а не Linux-сборку под CoreCLR. Некоторые округления knockback в Single различаются; проверка использует соответствующий платформенный fixture. Записи сохраняют хеши исходных сборок и фактические входные mode/GoodWorld.

Контроли на копии production выявляют устаревшие параметры матроса, неверное ускорение, пропуск второго смещения X, нормализацию совпадающих центров и медленное затухание alpha; восстановленные копии проходят без ошибок runner. Доказательства не закрывают полный планировщик Main, произвольные импортированные статусы/цели, Летучего голландца491/пушки492 или FullVanillaAiParity. Выбор вторжения и владение смертью описаны в [частоте естественного спавна](natural-spawn-rate.md) и [правилах добычи NPC](npc-loot-rules.md).
