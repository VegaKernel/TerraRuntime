# Инвентаризация NPC оригинала 1.4.5.8

Независимая инвентаризация выделенного сервера выполняет `NPC.SetDefaults` для каждого положительного и отрицательного идентификатора оригинала в классическом режиме. `NPCID.Count` равен `697`: положительные запросы — `1..696`. `NPCID.NegativeIDCount` равен `-66`: отрицательные запросы — `-1..-65`. Сняты 761 результата оригинала, включая последний идентификатор `696` с исходным AI style `127`.

Пять положительных идентификаторов (`76`, `146`, `403`, `404`, `408`) дают нулевую максимальную жизнь. Без них остаётся 691 определение NPC. На контрольной точке `2d71e8d8` runtime допускает 394 положительных определения и 36 знаковых вариантов; отсутствуют ещё 297 положительных определений и 29 знаковых вариантов. Допуск определения **не** означает полную поддержку AI, столкновений, добычи, статусов, окружения или синхронизации. Эти числа описывают инвентаризацию, а не процент готовности. `FullVanillaAiParity` остаётся false.

Полная выборка только фактов оригинала находится в [сжатой фикстуре](../../tests/TerraRuntime.Tests/Fixtures/npc-definition-manifest-official-1458.json.gz). Она содержит числовые параметры и идентификаторы, без игровых ресурсов, отображаемого текста и скопированных тел методов. [Тесты инвентаризации](../../tests/TerraRuntime.Tests/NpcDefinitionManifest1458Tests.cs) проверяют весь диапазон идентификаторов, исходный AI style каждого допущенного положительного определения и классические параметры допущенных знаковых вариантов. Новые допущенные идентификаторы автоматически попадают под эти проверки, а отсутствующие определения не считаются реализованными.

Для допуска новых семейств по-прежнему нужны трассы исполнения оригинала, владение целыми переходами и регрессии отказа. Более широкий объём работы отражён в [дорожной карте NPC](../roadmap/npc-ai-parity.md). Сборка оригинала выполнялась на Windows CoreCLR; эта инвентаризация не подтверждает Linux NativeAOT.
