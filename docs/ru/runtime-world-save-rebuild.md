# Пересборка runtime-world после канонического сохранения

[English](../en/runtime-world-save-rebuild.md) · [Сохранение мира](world-persistence.md) · [Дорожная карта](../roadmap.md)

## Контракт

Terraria-совместимый `.wld` всегда остаётся авторитетной точкой сохранения. Файл `.runtime-world` является только производным образом для быстрого запуска и перестраивается лишь после успешной публикации канонического сохранения.

```mermaid
flowchart LR
    A["Авторитетный snapshot"] --> B["Фоновая сериализация canonical .wld"]
    B --> C["Проверенная атомарная публикация .wld"]
    C --> D["Post-commit передача"]
    D --> E["Coalescing-очередь пересборки runtime image"]
    E --> F["Стабильное чтение canonical + полная проверка мира"]
    F --> G["Атомарная публикация .runtime-world"]
```

Ошибка runtime-image не откатывает и не изменяет уже успешно сохранённый `.wld`. Поэтому диагностика пересборки кеша учитывается отдельно от ошибок канонического сохранения.

## Coalescing

Канонические сохранения и пересборки runtime-image используют независимые ограниченные coalescing-планировщики. Одновременно выполняется не более одной пересборки кеша. Если во время неё успевают зафиксироваться несколько новых canonical checkpoint, лишние ожидающие пересборки схлопываются до самой новой генерации вместо накопления неограниченной очереди дискового I/O.

Worker читает canonical только после публикации. Он фиксирует метаданные источника до и после чтения, полностью проверяет поддерживаемый `.wld`, атомарно записывает runtime image, затем повторно проверяет источник. Если canonical изменился в этом окне, заведомо устаревший производный образ удаляется и worker повторяет попытку уже для более новой генерации.

## Завершение работы

При штатном shutdown авторитетный owner останавливается, ставится в очередь финальный canonical snapshot, после чего сначала полностью дренируется coordinator сохранения `.wld`. Успешный финальный commit ставит в очередь пересборку runtime-image. Затем завершение persistence ждёт опустошения очереди пересборки кеша.

Старое поведение shutdown удаляло `world.runtime-world` после финального сохранения. После появления финальной пересборки такая инвалидация неверна: свежий runtime image должен пережить shutdown и ускорить следующий запуск. Bootstrap packet cache по-прежнему инвалидируется отдельно, потому что этот блок его не перестраивает.

## Семантика ошибок

Пересборка может завершиться статусом недоступного источника, изменения источника во время чтения, невалидного canonical world, ошибки записи кеша или I/O. Эти результаты не превращают уже успешно опубликованный `.wld` в неудачное сохранение. При запуске производный образ остаётся необязательным: отсутствующий, устаревший или повреждённый runtime image приводит к безопасному fallback на canonical `.wld`.

## Проверка

Тесты покрывают post-commit границу callback, стабильную пересборку canonical в runtime-image, запрет замены существующего кеша из невалидного canonical-файла и полный final-save сценарий, где после завершения shutdown остаётся загружаемый runtime image, соответствующий только что сохранённому canonical checkpoint.
