# Исходный каталог определений NPC 1.4.5.8

[English](../en/npc-source-definition-roster-1458.md) · [Граница NPC runtime](npc-behavior-runtime-boundary.md)

Доступный для запросов каталог охватывает 691 из 696 положительных исходных идентичностей и все 65 signed-вариантов. Пять исключённых положительных ID (`76`, `146`, `403`, `404`, `408`) имеют нулевой исходный максимум жизни. Это все исходные defaults с ненулевой жизнью; показатель относится к определениям, а не к полному поведению NPC. У исходной идентичности `664` ненулевая жизнь, но нулевой размер тела: метаданные доступны, разрешение геометрии отклоняется.

Прежние 430 допущенных определений сохраняют приоритет и не меняются. Ещё 326 идентичностей (297 положительных, 29 signed) предоставляют классические исходные defaults с `DefinitionOnly = true`, `BehaviorFamily.None` и `PhysicsFamily.None`. Данные получены из 761 независимого вызова `SetDefaults` / `SetDefaultsFromNetId` оригинального dedicated server. Сохраняются только числовые факты; исходники игры, названия и assets не поставляются.

Новые метаданные сохраняют точный исходный hitbox после масштабирования. Не захваченные сырые размеры остаются нулевыми: деление округлённого тела на scale выдумало бы исходные размеры. `TryResolveHitbox` принимает только захваченный классический scale либо явно предоставленный корректный live hitbox. Масштабирование сложности, особых миров и настоящее создание NPC требуют отдельного подтверждения оригиналом.

Запрос определения не даёт права на автономный lifecycle. Vanilla-создание отклоняет строки метаданных до вызовов контекста, расхода RNG и выделения слота. Границы авторитетных vanilla AI/status/physics, ударов, контакта, ловли, классификации роли и смерти с неподдержанной добычей также отклоняют неуправляемое поведение. Явное ручное сохранение состояния и удаление остаются доступны. Намеренно зарегистрированное пользовательское поведение имеет собственного владельца; появление определения presentation identity не должно молча отключать это расширение.

Проекция `packet 23` для импорта только метаданных требует явно предоставленного текущего максимума жизни и корректного live hitbox override. Метаданные не должны заполнять неизвестные факты импортированной симуляции. Независимые байты оригинального `SendData` охватывают 326 новых идентичностей, включая signed-варианты, с полной и частичной жизнью. Encoder также записывает исходный release-owner byte для всех семи Gold NPC ID `442–448`; `TerrariaNpcUpdateState.ReleaseOwner` по умолчанию равен `255` и допускает явно принадлежащее владельцу байтовое значение. Эта правка протокола не даёт допуска их игровому lifecycle ловли и выпуска.

`FullVanillaAiParity` остаётся false. Порядок работы: live join acceptance, каталог определений, использование предметов/inventory/ammo/equipment, бой/баффы, события/invasions/progression, затем оставшаяся полная совместимость AI NPC. Прежний поведенческий прототип AI3/AI7 сохранён отдельно до приёмки настоящих state/wire/currentness доказательств.

Локальная проверка checkpoint: полный прогон 1562815/1562816, без failures/errors и с одним прежним skip жидкостей; 30 434 focused-проверки и fast tier прошли. Независимые source captures и отрицательные контроли проверяют разделение метаданных и lifecycle. Windows NativeAOT и все пять smoke-путей прошли. Восемь live socket-проверок на Release и NativeAOT подтверждают вход, relay/chat, lifecycle сундука и репликацию наблюдателям. Bootstrap населённого мира: 15 секций, один модуль Banner, 295 записей Bestiary, затем пакеты49/129 (312 кадров до49 включительно). Acceptance графического официального клиента и настоящий Linux NativeAOT не заявлены.
