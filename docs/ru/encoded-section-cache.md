# Контракт кэша закодированных секций

TerraRuntime кэширует уже закодированное представление секций мира в виде Terraria packet 10. Кэш является только производной сетевой оптимизацией; авторитетным состоянием плиток остаётся `WorldTileStore`.

## Инвалидация по ревизии

Каждая сетевая секция имеет чётный токен зафиксированной ревизии. `WorldTileStore.Set` изменяет токен вокруг записи плитки, а после фиксации помечает секцию грязной для двух независимых потребителей: сети и persistence. Кэшированный frame хранит ревизию, из которой он был построен, и никогда не возвращается, если текущая ревизия уже другая.

Мутация плитки не берёт lock кэша. Несовпадение ревизии является немедленной логической границей инвалидации, а память stale-frame освобождается лениво при следующем lookup или publication. Так hot path мутации остаётся дешёвым и детерминированным, а устаревшие байты не могут уйти клиенту.

Pinned bootstrap-секции подчиняются тому же revision-контракту, что и динамические. Они защищены только от LRU-вытеснения, но не от инвалидации.

## Построение и доставка

Базовые spawn-секции кодируются при создании `PlayerBootstrapPacketSet`. Остальные секции перестраиваются из immutable snapshots в ограниченном worker pipeline кэша. Результат worker публикуется только если захваченная ревизия всё ещё совпадает с зафиксированной ревизией живого мира.

Per-player streaming tracker обновляется только после того, как packet-10 frame успешно попал в outbound queue. Ошибка кодирования, stale-результат worker, rate limit или outbound backpressure поэтому не могут создать ложное состояние «секция уже доставлена».

## Начальная загрузка и генерация

Начальное построение мира использует `SetInitialPopulationTile`, который обходит ревизии секций и оба dirty tracker, пока мир ещё не опубликован. Поэтому загрузка/генерация не создаёт искусственный backlog на весь мир для сети и save pipeline. После публикации мира мутации обязаны идти через обычный отслеживаемый API.

## Ограничение памяти и наблюдаемость

Базовые bootstrap entries закреплены, потому что нужны каждому подключающемуся игроку. Остальные frames используют детерминированный LRU с бюджетом по умолчанию 64 MiB. Наблюдаемый общий потолок равен динамическому бюджету плюс `число base-секций * ushort.MaxValue`, то есть максимально возможному размеру Terraria frame для каждого закреплённого packet.

`SectionPacketCacheSnapshot` показывает число entries, текущие/максимальные bytes, dynamic bytes/budget, hits, misses, stale reads, waits, wait completions/failures/timeouts, evictions и физические invalidations. Все счётчики агрегированные, без меток на каждую секцию, чтобы сама телеметрия не стала новым неограниченным кэшем.

## Проверка

Gate `EncodedSectionCacheContractTests` доказывает инвалидацию dynamic и pinned entries по ревизии, двойной dirty tracking для живых мутаций, чистую initial population, маркировку доставки только после явного успеха и bounded-memory telemetry. `SectionCacheMemoryBudgetTests`, `PlayerSectionStreamingStateTests` и `SectionCachePriorityTelemetryTests` остаются дополнительной регрессионной защитой.
