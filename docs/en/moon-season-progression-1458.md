The authoritative clock applies the TerrariaServer `1.4.5.8` dawn sequence before clearing a Moon event: capture its total score, expire the previous temporary seasons, award the corresponding season if the event reached wave `15`, refresh the effective calendar seasons, and clear the event counters. The award remains active through the following night and expires at the next dawn. Repeating the qualifying event renews the flag without another start announcement.

`RuntimeWorldClock` owns `ForceHalloweenForToday` and `ForceXMasForToday`; the loaded `Forever` flags remain immutable. At dawn, `Forever` suppresses the corresponding `ForToday` flag. This can emit an end-of-victory announcement while the effective season remains active. Effective Halloween and Christmas use the existing source calendar predicates, evaluated at owned world load and dawn in Christmas-then-Halloween order.

Canonical world loading supplies all four flags. A partial host using only a scalar clock does not establish a seasonal baseline: `HasOwnedSeasonalState` stays false, and existing explicit seasonal facts remain authoritative. Missing facts do not become false saved flags. A complete owned clock overrides stale loaded seasonal facts in both directions.

The clock retains one immutable dawn notice, consumed by the production world loop after each clock tick. The accepted world/bootstrap state is refreshed before publication. The network order is score, Halloween flag change, Christmas flag change, then packet `7`. Score uses `Misc.PumpkinMoonScore` or `Misc.FrostMoonScore`, a literal float substitution, and the source boss/event color. Flag changes use `Misc.StartedVictoryHalloween`, `Misc.EndedVictoryHalloween`, `Misc.StartedVictoryXmas` or `Misc.EndedVictoryXmas` and the source world color. No progression-event packet is fabricated for the score.

The two temporary flags are persistent world fields, distinct from transient Moon waves. Detached saves and live packet `7` retain the accepted flags; late join receives the same owned snapshot. A death preview can copy a notice but cannot consume or publish its live counterpart.

A paid Moon invocation accepted on the final night tick publishes its announcement and start packets `7`/`78` before time advances into dawn. Rejected or repeated requests create no extra start publication. If an already published event gains progress on that final tick, the retained packet `78` wave snapshot precedes the score and reset. The existing pending-start phase distinguishes this from synthetic component setup that never published a start.
