# Ordinary ammo projectile death in 1.4.5.8

The represented nine bows and eight guns create projectile bodies `1`, `2`, `4`, `5`, `14` and `981`. Official 1.4.5.8 `Projectile.Kill` and `Kill_ExplodeTiles` create no recovered-ammo world item for any of these bodies. Physical ammo, conserved uses and Endless ammo therefore do not gain an inventory refund when these projectiles die. `CombatTrusted` alone is not inventory funding. No recovery balance, pending pickup, `NoDropItem` field or paid-origin field is introduced without a source producer.

The concrete world stepper retains the ordinary Update source offer with the existing bounded subupdate proposal. After generation-safe state adoption, the existing pre-publication simulation sink consumes the offers on the existing projectile RNG owner. Silver Bullet offers once per AI subupdate; tile collision offers before its owner/cutting gates; Unholy and Jester offer after movement when collision has not returned. Within this Update timeout/tile-collision path, Jester semantic Kill contributes sixty further arguments. World-bound deactivation happens before AI and contributes none. A state-only post decorator preserves the source observation. Missing RNG ownership refuses the proposal. Throwing publication cannot repeat accepted entropy or revive an old projectile generation.

Independent Linux and Windows original captures contain 350 direct Kill cases and 120 actual Update timeout/collision cases per run. Each first run has an exact repeat: 1,880 rows, zero capture errors. The direct Kill harness includes projectile `155` producing item `859` as an allocation control; this projectile is outside the admitted ammo roster. Dedicated Update checkpoints compare the full RNG state and next value. Production checks cover all 240 first-run Update rows, phase-paid Jester expiry with funded and zero-funded physical ammo, duplicate reports, observer failure, generation reuse and behavior composition.

These are projectile Update timeout/tile-collision component checks. NPC-hit/penetration removal and explicit client removal use other termination paths; their Kill entropy remains unverified by this change. These results do not establish whole-Main RNG parity, new NPC combat admission, GUI behavior, Linux NativeAOT execution or new recovery/persistence support. Existing world-item custody and persistence remain the owners for genuine item producers. Four cycling accessories remain outside this scope.
