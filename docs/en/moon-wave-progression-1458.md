# Authoritative Moon wave publication

Pumpkin Moon and Frost Moon use one authoritative wave/kill/total score owner. An accepted participant death adds its source points with the Classic/Expert/Master multiplier `1`/`2`/`2.5`, advances at most one wave, and discards surplus wave points. Wave `20` is endless with requirement `0`. The destination-wave announcement uses the exact ordered participant names from the local TerrariaServer `1.4.5.8` source. Wave `15` remains a numbered wave; only wave `20` uses `Game.FinalWave`.

The retained death journal captures immutable `MoonEventDeathEffects1458` during isolated planning and adopts the counters before notifications. It refreshes the immutable join bootstrap after all accepted state changes and before its first public callback. Its publication order is loot, wave text (`82`), the wave-15 achievement (`98`: Frost `14`, Pumpkin `15`), conditional progress (`78`), and terminal NPC state (`23`). A throwing callback does not reopen the accepted death or skip the retained publication tail. A newer nested death suppresses obsolete outer wave text/progress; the older accepted achievement still drains once through its local journal.

The ownership revision and source progress predicate are separate. Vanilla sends `78` only when the wave-kill float changed and the credited points were nonzero. A high-point kill starting at zero can advance a wave, reset to zero and send only its wave text. At float32 precision limits a credited point can leave the counter unchanged and send no progress packet. The replication owner acknowledges these accepted revisions as handled, preventing periodic polling or the retained last-night/dawn path from fabricating a duplicate `78`. Late join still receives the accepted current wave and real requirement.

The corresponding active event family owns the death's icon and achievement even in a component context exposing both Moon flags. Shared counters and the source Snow-priority dawn score remain intact. Canonical paid starts remain mutually exclusive.

The larger protocol-addressable `256`-slot Core custom-host API remains available with its existing refusal rules; it is not used to size the vanilla world. This keeps source-qualified spawn, paid-boss and Captain child producers connected to the same physical table as terminal journals.
