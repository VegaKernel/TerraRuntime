# World generation source tools

`tools/vanilla.py worldgen` provides a source registration catalog, a bounded replay of one compiled Reset checkpoint, and fresh original/runtime execution of supported isolated passes. These workflows do not generate a complete world or prove complete pass parity.

```sh
python tools/vanilla.py worldgen capture --source-root /path/to/decompiled/1458 --output .cache/worldgen-tools/catalog.json
python tools/vanilla.py worldgen check --reference .cache/worldgen-tools/catalog.json --source-root /path/to/decompiled/1458 --report .cache/worldgen-tools/check.json
python tools/vanilla.py worldgen mutate --reference .cache/worldgen-tools/catalog.json --report .cache/worldgen-tools/mutations.json
python tools/vanilla.py worldgen replay-reset --tests-dll tests/TerraRuntime.Tests/bin/Release/net11.0/TerraRuntime.Tests.dll --output-dir .cache/worldgen-tools/reset-replay
python tools/vanilla.py worldgen run-pass --assembly /path/to/TerrariaServer.exe --output-dir .cache/worldgen-tools/grass-wall --seed 1458
python tools/vanilla.py worldgen run-pass --assembly /path/to/TerrariaServer.exe --output-dir .cache/worldgen-tools/quick-cleanup --seed 1458 --profile quick-cleanup
python tools/vanilla.py worldgen run-pass --assembly /path/to/TerrariaServer.exe --output-dir .cache/worldgen-tools/cleanup-shapes --seed 1458 --profile quick-cleanup-shapes
python tools/vanilla.py worldgen compare-pass --official .cache/worldgen-tools/grass-wall/official.json --runtime .cache/worldgen-tools/grass-wall/runtime.json --report .cache/worldgen-tools/grass-wall-comparison.json
```

Use `py -3` instead of `python` on Windows if needed. Capture/output/report paths must be new. `--repo` on catalog check/mutate selects another checkout. The replay requires an existing compiled test artifact; it does not build one.

## Registration catalog

Capture reads the official 1.4.5.8 source, checks release/version, records raw source and tool hashes and extracts all 109 lexical registrations before special-seed filtering. It resolves pass names, order, outer registration conditions, legacy/typed weights and the dual-dungeon disabled-name list. Comments and literals cannot create fake declarations; unknown outer syntax or conditional compilation is refused instead of guessed. Delegate implementations are identified by hashes, not copied into the capture.

Check compares the runtime `PassCatalog1458` name sequence, registration/method fingerprints and dual-dungeon filter. The runtime catalog does not store individual weights or the full registration predicates, so those are explicitly **unrepresented** or **recorded but not executed**. Generated cells and RNG are **not executed** by this check. Without `--source-root`, current source freshness is explicitly not rechecked; with it, changed source inputs reject the reference. The capture is a provenance record, not an attestation of behavior.

Mutation checks require a green baseline and then corrupt five named metadata cases in memory: first-pair order, final name, body fingerprint, filter entry and the pass-array declaration. A red baseline never becomes a green mutation result. Production catalog files are never modified.

The initial real-source audit on 2026-10-28 intentionally returns a diagnostic failure: all 109 names/order, registration-expression/name hashes and dual-dungeon filtering agree, but the current source `AddPasses` method hashes to `1e073711995e1eb38578d7d23e991cf5005fefaf573188ebbdcec261f945347f`, while the production catalog records `72e757af1fb0a7b565d397bbb0f9fd1d32a2960838ba636c593e122645ab9672`. The unchanged earlier source reader independently reproduces the new hash. A fresh CI-style decompile with the historical pinned Windows assembly/ILSpy version also reproduces it. The retained log of [historical CI run 33268133716](https://github.com/VegaKernel/TerraRuntime/actions/runs/33268133716) really printed the old hash; its full method-body artifact has expired. Other logged methods show decompiler output differences beyond whitespace, but they do not establish equivalence of the unavailable historical `AddPasses` body. Simple whitespace/comment transformations did not bridge the hashes. The exact cause remains unresolved: no runtime constant was changed and agreement of names is not treated as body equivalence.

## Fresh isolated-pass comparison

`run-pass` builds the current offline `PassProbe` with warnings as errors, validates the official executable and dependencies against the admitted reference, and captures both engines in separate processes. It selects the actual registered official pass and calls `GenPass.Apply`; the runtime capture calls the corresponding current runtime `Apply`. Neither pass implementation is copied into the tool. `--profile grass-wall` remains the default; the two cleanup profiles select distinct explicit fixtures.

| Profile | Official registration / runtime body | Explicit synthetic predecessor |
| --- | --- | --- |
| `grass-wall` | `SurfaceDirtWallsToGrassWalls` / `Grass Wall`; `GrassWallPass1458.Apply` | 160×112 stone/wall patch; all 17,920 cells |
| `quick-cleanup` | `QuickCleanup` / `Quick Cleanup`; `QuickCleanupPass1458.Apply` | 800×160 ordinary-world cleanup cases; all 128,000 cells |
| `quick-cleanup-shapes` | `QuickCleanup` / `Quick Cleanup`; `QuickCleanupPass1458.Apply` | 800×160 independent half-brick/slope cases; all 128,000 cells |

Both engines receive the same explicit predecessor, world context and RNG state. The observations contain every cell before and after in the complete named 16-byte `WorldTile` projection, plus the physical RNG cursor and all 56 state slots. In 1.4.5.8, `WorldGen.genRand` aliases `Main.rand`; the second RNG cursor is derived, not an additional stored field. The comparator rejects different input cells, context, scenario or RNG before comparing every output field and reporting the first cell/field and RNG difference. Missing, malformed or unsupported represented state is rejected.

The ordinary cleanup profile covers ocean liquid normalization above/below its floor and inside/outside its columns, sand support columns with RNG drawn in the loop condition, hive/temple materials and shallow/deep liquids, wall borrowing, and ordinary slope/support/trap cases. The official readonly beach distance remains 380; the fixture preserves a genuine inland strip. Both cleanup contexts additionally record rock layer, ocean level, beach distance, ordinary seed flags, and independently observed participating solidity, solid-top, saved-slope, platform and generation-clearability facts. Missing facts for any input/output cell identity or different content facts reject comparison. The original facts are initialized from verified source setup for these identities; this is not full content initialization. Combined independent half-brick/slope shapes have their own profile; secret-seed branches remain outside both.

`quick-cleanup-shapes` applies the tool to a shipping bug: the old pass assumed half-brick and slope were mutually exclusive. Actual original/current execution on identical full input reproduced seven differing cells and equal RNG; the old runtime also left an invalid `HalfBrickWithSlope` flag beside `Shape=0`. The grouped normal regression failed against that old production body before the fix. Cleanup now clears both fields when vanilla calls `ClearSlope`, preserves half-brick when vanilla clears only the slope of an ocean sand anchor, and gives the half-brick support test and Pearlstone exception precedence over a simultaneous bottom slope. Platforms and generation-protected materials preserve both fields. Unrelated metadata and RNG are retained. The original red observations and failing test XML remain under `.cache/worldgen-shapes-applied/old-01`; the pass audit remains `C`, not a whole-pass or natural-prefix acceptance claim.

After the fix, fresh backend captures match all 128,000 cells and full RNG for seeds `1458`, `42` and `8675309`, with 20, 18 and 20 changed cells respectively. The seed-1458 original input/output is byte-identical to the original side of the red reproduction. Actual omission detects 20 differing cells plus RNG; an extra draw detects RNG only. Fresh ordinary-cleanup and Grass Wall pairs still match. Warnings-as-errors builds pass, and the new grouped regression plus existing cleanup/surface-finish regressions pass 21/21 without failures/errors/skips. These backend observations and focused XML are retained under `.cache/worldgen-shapes-applied/fixed-01/qualification.json`; this is not a claim of a completed cross-domain source-guard, full-suite or Native gate.

This repair is limited to Quick Cleanup. A read-only sibling audit found other legacy shape-only writes or predicates in cave-house, chest, cactus, cattail and dungeon code; those are candidates for separate source-backed execution, not verified fixes or a general combined-shape parity claim.

`run-pass` records source/tool hashes and the executed DLL closure, checks them before/after, and retains build/capture logs and rejected evidence. `compare-pass` only compares the supplied observations and records the hashes of the consumed files; it does not rebuild or recheck their correspondence to current source. The Grass Wall fixture exercises wall staining and deliberately excludes dirt-pocket/`SpreadGrass` branches. None of these profiles represents a naturally generated prefix, raw `Tile` wall-frame metadata, the `WorldGenerator.RunPass` manifest-tail RNG draw, Native execution or whole-world parity.

The actual 2026-10-28 qualification used fresh `run-pass` executions for seeds 1458, 42 and 8675309: all 17,920 output cells and RNG states matched, with 1,832 source/tool inputs and six DLLs unchanged in each run. Two actual runtime controls confirmed detection: `--control omit-pass` produced 83 differing cells and an RNG difference at seed 1458; `--control extra-rng` preserved cells but changed RNG. Both controls correctly return a rejected comparison and nonzero CLI exit. Their evidence is retained under `.cache/worldgen-run-pass-root-01`, `-42`, `-8675309`, `-omit` and `-extra`; these local captures are not portable golden files.

The second-profile backend qualification on the same date freshly built `PassProbe` with zero warnings/errors and captured the actual registered Quick Cleanup delegate and runtime body for seeds 1458, 42 and 8675309. Every one of the 128,000 cells and the complete RNG state matched; the pass changed 67, 62 and 65 cells respectively, so these are not empty-world no-op comparisons. At seed 1458 the real omitted-pass control differed in 67 cells and RNG; the extra-draw control differed only in RNG. A freshly captured Grass Wall pair still matched. The backend checks its DLL closure and official inputs before/after; these prototype captures do not claim the common runner's across-build source guard. Full observations and comparison evidence are retained under `.cache/three-oracles-worldgen/prototype-01/qualification.json`.

Final shared CLI qualification executes `quick-cleanup` for seeds `1458`, `42` and `8675309`, both real negative controls, and the preserved Grass Wall profile. Source/tool and DLL guards remain exact throughout. The [three-domain verification record](../verification/three-domain-oracles-20261028.json) retains hashes, comparison details and measured runner times; this does not extend the stated profile scope.

## Reset replay and the next differential step

Replay invokes exactly `VanillaReferenceDifferentialCheckpoint1458Tests.Official_reference_seed_8675309_keeps_pinned_reset_dungeon_side_and_anchor` through the supplied xUnit DLL. It saves stdout/stderr, audits actual XML for exactly that one passing test with no failures/errors/skips, hashes the complete discovered DLL closure before/after and retains rejected evidence. Timeout is $60\,\mathrm{s}$. It refuses existing output directories. A successful replay proves the supplied compiled artifact still passes the existing official Reset checkpoint; it does not prove that the artifact matches current source, execute the original game again, compare every world cell or run all generation passes.

The official `WorldGenerator.Controller` already offers pause-after-pass and `WorldGenSnapshot` create/restore. That is a useful foundation for a future real-prefix, individual-pass oracle. A snapshot contains manifest/GenVars and canonical tile/chest/tile-entity data; restore deactivates NPCs and does not reproduce arbitrary raw in-memory state. Intermediate manifest hashes can be absent, and their comparison tolerates absence, so a future oracle must require explicit supported before/after state, its own canonical cell hashes and observed RNG endpoints. `Main.rand` is recreated from the generator seed before each pass; this must not be confused with continuity of other RNG owners.

`TerraRuntime.WorldCompare` checks structural budgets of final `.wld` files. It is useful for silhouettes/histograms and related checks, but it is not an exact first-cell/RNG differential. No general exact-world oracle or automatic C# algorithm translation is introduced here.
